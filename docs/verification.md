## 2. 기준값

모두 코드에서 상수로 분리했다. 실차 데이터로 다시 맞춰야 하는 값이다.

| 항목 | 값 | 위치 |
|---|---|---|
| 수동 기록 길이 | 직전 60초 | `RingRecorder`, `RecordSaver` |
| 추정 지점 | 브레이크 구간 중 가장 큰 1초, 없으면 60초 중 가장 큰 1초. 앞뒤 5초를 대표 구간으로 | `core/PointEstimate.kt` |
| 공통 조건 채택 | 기록 중 포함률 75% 이상, 평소 주행의 2배 이상 | `core/Conditions.kt` |
| 공통 조건 계산 최소 | 기록 2개, 평소 주행 30초 | `core/Conditions.kt` |
| 조건 구간 | 속도 10km/h 단위, 핸들 15°/90°, 바깥 온도 10°C/25°C | `core/Conditions.kt` |
| 자동 포착 | 조건 시작 3초 뒤 저장(조건 7초 전 ~ 3초 후 소리), 같은 증상 30초 안 재저장 없음 | `core/AutoCaptureJudge.kt` |
| 재발 판단 | 수리 전 특징 대역보다 6dB 넘게 줄지 않으면 재발 기록 | `core/SoundAnalysis.kt` |
| 링 버퍼 | 48kHz(실패 시 44.1kHz) 모노 16비트, 약 5.6MB | `audio/Audio.kt` |

## 4. 시연 데이터가 만드는 값

시연 데이터(`demo/DemoPlan.kt`)는 수리 뒤 끼익 소리를 일부러 약 -20dB(진폭 0.25 → 0.025) 작게 넣는다.
앱은 이것을 "수리 전 특징 대역(1~2kHz)이 평균 -19dB"로 계산했다(2026-11-14 화면).
같은 화면의 공통 조건은 "차가운 날(바깥 10도 이하), 시속 20~40km, 브레이크 중 — 4회 중 4회 (평소 주행에서는 이 조건이 1%)"였다.
