# 발전 계획

## 1차 제출(2026-11-14)에 들어간 것
녹음(직전 10초) · 주행 신호 1초 요약 · 주행 중 큰 버튼 기록 · 증상 묶기와 공통 조건 · 자동 포착 · 정비소 리포트(PDF) · 수리 후 확인(대역 에너지 비교) · 글레오 조회 함수 · 창문 자가 점검 흐름(실차 전제) · 시연 데이터.

## 2차 계획

### 사람 말소리 보호: 음성 구간 무음 처리
- 지금: 원본 소리는 기기 안에만 저장, 직전 10초만 메모리에 보관, 기록별 삭제와 "녹음 파일 모두 삭제" 제공.
- 계획: 저장 직전에 음성 구간을 찾아 그 부분만 무음으로 바꿉니다.
  - 1단계: 에너지 + 영교차율 + 300~3400Hz 대역 비율로 음성 후보 프레임(20ms) 판정, 앞뒤 200ms 여유를 두고 무음 처리. 기존 Kotlin FFT로 구현 가능.
  - 2단계: 온디바이스 VAD 모델(예: 경량 신경망)로 교체해 정확도 향상.
  - 차 소리 대역(브레이크 끼익 1~4kHz)과 사람 말소리 대역이 겹치므로, 무음 처리 비율을 리포트에 표시해 정비사가 판단할 수 있게 합니다.
- 설정에서 켜고 끌 수 있게 하고, 기본값은 켜기로 합니다.

### 리포트 공유: 서버·QR
- 지금: 리포트를 A4 PDF로 `Download/SymptomNote`에 저장.
- 계획:
  1. 리포트(텍스트·그래프)와 대표 소리(말소리 무음 처리본)를 서버에 올리고 짧은 URL 발급
  2. 차 화면에 QR 코드 표시 → 정비사가 휴대폰으로 열람(로그인 없이, 7일 뒤 자동 삭제)
  3. 정비 결과(수리 내용·날짜)를 정비사가 입력하면 앱의 "수리 완료"에 자동 반영
- 개인정보: 업로드 전 동의 화면, 위치 정보 미포함, 원본 녹음은 올리지 않음.

### 그 밖에
- 공통 조건 기준값(포함률 75%, 배율 2배, 핸들·온도 구간, 재발 -6dB)을 실차 기록으로 조정.
- 창문·시트 외 자가 점검(와이퍼, 트렁크) 추가. 실차에서 제어 후 실제 값 변화와 소리 비교 검증.
- 글레오 음성 호출과 상시 녹음 공존: `docs/platform-findings.md`의 플랫폼 개선이 이루어지면 "증상노트, 방금 소리 기록해" 함수 추가.
- 운전대 버튼으로 기록: 실차에서 서드파티 앱에 오는 키 코드 확인 후(verify 5-24 미확인) 지원.
