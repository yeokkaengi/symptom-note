# 플랫폼 확인 사항: 녹음 중 글레오 호출 불가

근거: `../verify-app/README.md` 탭 5 (5-15, 5-16, 5-19, 5-22, 5-23), Pleos Connect v2.1.0 에뮬레이터(Android 14, 사용자 10).

## 1. 현상

증상노트는 "방금 난 소리"를 남기기 위해 **직전 60초 링 버퍼**를 마이크 포그라운드 서비스(FGS)에서 계속 녹음합니다.
그런데 이 녹음이 켜져 있는 동안에는 **글레오 음성 호출이 동작하지 않습니다.**

| 상황 | 결과 | 근거 로그 (verify 5-19) |
|---|---|---|
| 앱 화면이 보이고 링 버퍼 켜짐 | 글레오 창이 떴다가 바로 닫힘 | `[GAA] isUsingPrimaryMic: true` → `preProcessSystemEvent() : isUsingPrimaryMic is activated, ignoring` |
| 설정 앱으로 앱을 가리고 링 버퍼 켜짐 | 같음(4번 모두 무시) | 같은 로그 |
| 링 버퍼 끔 | 정상 진행, 앱 리시버 수신 | `isUsingPrimaryMic: false` → `requestAudioFocus ... USAGE_ASSISTANT` → 앱 `receiver` 수신(5-16) |

- 호출어 감지(`onWakeUpDetected`)는 됩니다. 다른 앱이 마이크를 쓰고 있으면 **글레오 앱이 스스로** 대화를 시작하지 않습니다.
- 이 앱(`ai.symptomnote`)에서도 녹음을 켜면 상태 표시줄의 초록 글레오 마이크 아이콘이 사라지는 것을 보았습니다(2026-11-13 화면 캡처).

## 2. 시도한 해결책 (모두 verify-app 에서 실측)

| 시도 | 방법 | 결과 |
|---|---|---|
| 화면 양보 | 앱을 가려 백그라운드로 보냄(5-19 경우 B) | **효과 없음**. 글레오는 화면이 아니라 녹음 여부를 봄 |
| 녹음 양보 | `AudioManager.registerAudioRecordingCallback`으로 다른 앱 녹음이 시작되면 우리 `AudioRecord.stop()`(5-22) | Pleos STT와는 **동작**(감지→멈춤 114ms, STT 무음 해제). 글레오에는 **효과 없음**: 글레오는 새 녹음을 시작하기 *전에* 우리 녹음을 보고 포기하므로, 양보할 신호(다른 녹음 시작)가 생기지 않음 |
| 오디오 포커스로 감지 | 글레오의 포커스 요청을 미리 알아채기(5-22) | **불가**. 글레오는 마이크 검사를 통과한 뒤에야 포커스를 요청하고, 무시할 때는 요청하지 않음 |
| 마이크 분리 | 링 버퍼를 뒷마이크(`id=57 Built-In Back Mic`)로 `setPreferredDevice`(5-23) | **효과 없음**. `getRoutedDevice → id=57` 확인 후에도 `isUsingPrimaryMic: true` |

5-19(주 마이크)와 5-23(뒷마이크) 모두 `true`였으므로, 글레오는 특정 장치가 아니라 **다른 앱의 MIC 소스 녹음 여부**를 보는 것으로 추정합니다(로그 두 개에서 나온 추정이며 글레오 코드·문서로 확인하지는 않았습니다).

## 3. 증상노트의 대응

- 녹음을 시작하는 글레오 함수는 만들지 않았습니다. 대신 **녹음이 꺼진 상태에서 쓰는 조회용 함수**만 두었습니다.
  - `READ_SYMPTOM_SUMMARY`: 최근 증상 요약 읽어 주기
  - `HOW_TO_START_RECORDING`: 기록 시작 방법 안내
- 주행 중 기록은 화면의 큰 버튼(주행 중 기록 화면, DO 선언)으로 합니다.
- 리시버는 `"<패키지>.<함수 이름>"`(글레오 실제 형태, 5-16)과 `"<함수 이름>"`(문서 예제 형태) 두 action을 모두 받습니다.
- 글레오는 응답을 20초 기다리므로(5-15) 계산을 10초에서 끊고 응답합니다.

## 4. 플랫폼 개선 제안

1. **어시스턴트 호출과 앱 녹음의 공존 정책**: 사용자가 명시적으로 호출어를 말한 경우에는, 다른 앱의 상시 녹음을 잠시 무음 처리(Android의 `silenced` 메커니즘)하고 글레오가 마이크를 우선 사용하도록 하는 방식을 제안합니다. 지금은 글레오가 호출 자체를 포기합니다.
2. **양보 신호 제공**: 글레오가 대화를 시작하려 할 때 앱이 받을 수 있는 방송(예: "어시스턴트가 마이크를 쓰려 함")이나 콜백이 있으면, 앱이 녹음을 멈춰 양보할 수 있습니다(5-22에서 STT와는 이 방식이 동작함).
3. **앱 내부 버퍼 저장 함수의 예외**: `component: "service"` 함수가 "이미 녹음 중인 버퍼를 저장"만 하는 경우, 글레오가 마이크를 쓰지 않고도 실행할 수 있도록 하는 텍스트/버튼 호출 경로가 있으면 좋겠습니다.
4. **문서 보완**: 실제 호출 action에 패키지 접두가 붙는 점(5-16), 응답 대기 시간이 20초인 점(5-15, 문서는 7초)을 문서에 반영하면 개발자가 덜 헤맵니다.
